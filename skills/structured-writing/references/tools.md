# 六个工具表

> 何时读：需要具体框架时按需查阅，不必全文加载。
> 配合写模式与审模式使用的六张速查表。前五张是金字塔原理体系里的通用框架，
> 第六张「现有结构库」汇总的是各领域公认的分析模型。

---

## 工具 1 · 识别概括技术应用表

**用途**：读懂别人的文档 / 会议发言，用于审模式和信息接收。

| 步骤 | 做什么 | 产出 |
|---|---|---|
| **① 识别** | 通读一遍，把文中的**事实**、**理由**、**结论**分别标出来 | 三份清单 |
| **② 判断** | 画出实际结构：哪条支撑哪条，哪些是并列关系 | 一张结构图 |
| **③ 概括** | 用一句话概括中心思想 | 一个主题句 |

**四个辅助问题**（识别阶段逐个问）：

1. 哪些句子是**观点**（可以被反驳的判断）？
2. 哪一个观点是**总结论**？
3. 支持这个结论的**理由**有哪几条？
4. 抛开所有判断，纯粹的**事实**有哪些？

第 4 问的作用是把「事实」和「对事实的解读」分开。很多争论其实是解读之争，
事实并无分歧。

**诊断信号**：第 ③ 步概括不出来 —— 原文没有中心思想，这是最严重的结构问题。

## 工具 2 · 关系 → 图示对照表

> **注意：这是一份通用对照表，按图示表达原则整理，不对应任何特定教材。**

先想清楚要素之间是什么**关系**，再选图示。反过来做（先选好看的图再往里塞内容）
是 PPT 变花架子的主要原因。

| 要素关系 | 图示 | 用于 |
|---|---|---|
| 并列，无先后 | 并列色块 / 卡片网格 | 三个方向、四个模块 |
| 有先后顺序 | 箭头流程图 | 流程、步骤、阶段 |
| 循环往复 | 环形箭头 | PDCA、迭代闭环 |
| 层层包含 | 同心圆 / 嵌套框 | 范围、边界、圈层 |
| 逐级递进 | 阶梯 / 上升箭头 | 成熟度、发展阶段 |
| 自上而下分解 | 树形 / 组织架构图 | 金字塔结构本身、逻辑树 |
| 两维交叉 | 2×2 四象限 | 优先级、分类定位 |
| 对立比较 | 左右对照 / 天平 | 方案对比、改前改后 |
| 部分与整体 | 饼图 / 堆叠条 | 构成占比（≤6 项） |
| 随时间变化 | 折线图 | 趋势 |
| 量的大小比较 | 条形图 | 排名、对比 |

**选图三问**：这是什么关系？这个图示准确表达了这个关系吗？去掉装饰后还看得懂吗？

## 工具 3 · 5W2H 问题描述框架

**用途**：把一个模糊的问题描述完整，用在「描述问题定方向」阶段。

| | 问什么 | 追问 |
|---|---|---|
| **What** | 问题是什么？ | 现象还是原因？说的是同一件事吗？ |
| **Why** | 为什么会发生？ | 这是根因还是表象？往下再问一层 |
| **Who** | 涉及谁？谁负责？谁受影响？ | 谁是决策人？ |
| **When** | 什么时候开始的？什么时候必须解决？ | 有截止日期吗？ |
| **Where** | 在哪个环节 / 区域 / 系统？ | 范围有多大？ |
| **How** | 目前是怎么处理的？ | 已经试过什么？为什么没解决？ |
| **How much** | 影响多大？成本多少？ | 有量化数字吗？ |

**配套的 R1 → R2**：

- **R1 现状**：现在的结果是什么，哪里不满意
- **R2 期望**：希望变成什么样，可衡量
- **差距** = R2 − R1，这就是这份文档要解决的问题

R1 和 R2 都必须可衡量。「效率低」不行，「单据处理平均 3.5 天，目标 1 天」才行。

## 工具 4 · 基于目标定主题检查表

**用途**：动笔前过一遍，任何一条答不上来就不要往下写。

### 场景

- [ ] 时间：什么时候发 / 讲？
- [ ] 地点：正式会议、口头、还是群里发文？
- [ ] 人物：谁看？几个人？职级？他们最关心什么？

### 目标

- [ ] 说完之后，希望对方做的**具体行为**是什么？
- [ ] 这是从对方角度出发的吗？
- [ ] 这个行为在当场能达成吗？

> ✗ 「让领导了解项目进展」——不是行为
> ✓ 「让领导批准把上线时间从 10 月推到 11 月」——是行为

### 主题

- [ ] **简单**：一句话说完了吗？
- [ ] **准确**：指向明确，没有「若干」「相关」「进一步」这类虚词？
- [ ] **利益**：从对方角度说清了对他有什么用？
- [ ] 这是**结论**不是**话题**？

> 话题 → 结论的改写：
> 「Q3 工作总结」 → 「Q3 目标达成 112%，但获客成本上升 30%，建议 Q4 收缩投放渠道」

### 序言 SCQA

- [ ] **S** 里的每一句，读者都已经知道或一定会认同？
- [ ] **C** 和 S 直接相关，没有跳跃？
- [ ] 把 S+C 念给读者，他会自己问出 **Q** 吗？
- [ ] **A** 和上面定的主题是同一句话吗？

## 工具 5 · 5W2H 疑问回答式设想问题框架

**用途**：自上而下分解时，站在读者角度设想他会问什么，确保覆盖不漏。

给出结论后，逐个过一遍读者可能问的：

| 维度 | 读者的问题 | 什么时候必答 |
|---|---|---|
| **What** | 具体指什么？范围多大？ | 几乎总是 |
| **Why** | 为什么？依据是什么？ | 需要说服时 |
| **Who** | 谁来做？谁负责？谁受影响？ | 涉及执行时 |
| **When** | 什么时候？多久？截止什么时候？ | 涉及执行时 |
| **Where** | 在哪儿？哪个环节？ | 有空间/环节差异时 |
| **How** | 怎么做？分几步？ | 需要落地时 |
| **How much** | 多少钱？多少人？投入产出比？ | 要资源时 |

**简化版 2W1H**（大多数场合够用）：**What → Why → How**

**回答的四条规则**：

1. 每个答案必须是**结论**，不是话题
2. **每个层级**都要是结论，不只最上面一层
3. 下面每一条都在回答上面那个问题（以上统下）
4. 不同分类的问题，配不同分类的答案

## 工具 6 · 现有结构库

**用途**：分类时不必从零发明，直接套用现成的「筐」。套用现成模型是保证 MECE 最省力的办法。

### 通用

| 模型 | 切分维度 |
|---|---|
| **5W2H** | What / Why / Who / When / Where / How / How much |
| **人财物** | 人力 / 资金 / 物资（可加：时间、信息） |
| **时间** | 过去 / 现在 / 未来；短期 / 中期 / 长期 |
| **空间** | 内部 / 外部；总部 / 区域 |
| **PDCA** | 计划 / 执行 / 检查 / 改进 |
| **金字塔层级** | 战略 / 战术 / 执行 |

### 分析问题

| 模型 | 切分维度 |
|---|---|
| **SWOT** | 优势 / 劣势 / 机会 / 威胁 |
| **鱼骨图（6M）** | 人 / 机 / 料 / 法 / 环 / 测 |
| **PEST** | 政治 / 经济 / 社会 / 技术 |
| **逻辑树** | 沿一条主干逐层拆分到可执行 |

### 业务

| 模型 | 切分维度 |
|---|---|
| **4P** | 产品 / 价格 / 渠道 / 促销 |
| **价值链** | 研发 / 采购 / 生产 / 销售 / 服务 |
| **漏斗** | 曝光 / 点击 / 转化 / 复购 |
| **平衡计分卡** | 财务 / 客户 / 内部流程 / 学习成长 |

### 2×2 矩阵（自建 MECE 的万能工具）

找两个**互相独立**的维度做交叉，天然不重不漏：

| 常用组合 | 横轴 | 纵轴 |
|---|---|---|
| 优先级 | 紧急 ↔ 不紧急 | 重要 ↔ 不重要 |
| 问题处理 | 影响面大 ↔ 小 | 修复成本高 ↔ 低 |
| 产品定位 | 价格高 ↔ 低 | 频次高 ↔ 低 |
| 人员盘点 | 能力强 ↔ 弱 | 意愿高 ↔ 低 |

**选维度的要求**：两个维度必须**互相独立**。
用「成本」和「价格」做两轴不行——它们相关，四个象限里有两个是空的。

---

## 用法提示

套用现成模型时，**不要为了凑齐格子而硬填**。
SWOT 里 W（劣势）确实没有，就写「无显著劣势」，不要编一个凑数。
硬填出来的格子，读者一眼就看得出来。
